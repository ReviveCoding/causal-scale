# Security Policy

## Reporting

Use GitHub Issues for non-sensitive reproducibility defects and ordinary bugs. Before opening an issue, remove local paths, dataset rows, credentials, tokens, and other private material from logs or examples.

For accidental secret exposure, unsafe data exposure, private-key material, or another security-sensitive defect, use GitHub's private vulnerability reporting for `ReviveCoding/causal-scale` when it is available. If it is not available, open a minimal non-sensitive issue requesting a private maintainer contact; do not include the sensitive details.

Never post credentials, proprietary data, raw participant-level outcomes, or exploit details in a public issue. Reports should identify the affected version, impact, and safe reproduction steps when possible.

## Scope

Security reports may cover the published source, dependency or build integrity, evidence-verification defects, accidental inclusion of forbidden data, and bypasses of prospective-outcome guards. Scientific disagreements without a security or integrity impact belong in a regular issue.
